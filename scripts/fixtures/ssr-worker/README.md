# Packed SSR worker proof

This private fixture locks Wrangler, its workerd runtime and the optional framework peers used by the four SSR bridge imports. It is CI tooling and is not published with Material. CI runs `npm ci --ignore-scripts --no-audit --no-fund --prefix scripts/fixtures/ssr-worker`, then `bun run ssr-worker:check` against the build job's distribution.

The consumer packs and installs the release-staged package. Vite builds it with `ssr.target: "webworker"`, `ssr.noExternal: ["material"]` and `ssr.resolve.conditions: ["workerd", "worker", "browser"]`. All five SSR subpaths must resolve to, and load, their installed server files. Framework peers remain external at this stage; Wrangler resolves and bundles the real installed peers for local execution. There are no aliases to source files or fake framework modules.

Wrangler 4.160.0 / workerd 1.20261110.1 run locally at compatibility date 2026-11-10. Both `no_nodejs_compat` and `no_nodejs_compat_v2` are explicit because recent compatibility dates enable Node compatibility by default. The check asserts Wrangler's effective compatibility mode and the absence of worker-global `process` and `Buffer`. The bundle uses production mode and Vue's standard compile-time feature flags. Vue's own `__VUE__` renderer marker is allowed; temporary DOM globals and every captured native descriptor must be restored. No deployment, account or remote bindings are used; configuration, logs and temporary state stay in the consumer fixture.

The first dependency captures the worker's actual native globals and their own/prototype descriptors before the renderer and side-effect bridge imports evaluate. One cold realm must register all four bridges, render declarative roots through the public React, Vue, Svelte and Solid components using their real frameworks, restore descriptors and identities after success, roll back a deliberate in-scope failure and a partial installation failure, render again, and serve a later request. An inert-scheduler probe must never run its queued callbacks. Seeded inline/link output and all four framework render results must equal the same installed renderer's Node output.

The companion `ssr-consumer:check` covers all five SSR subpaths under ordinary Node/Bun, browser+node, workerd+browser, worker+browser and an unknown condition. NodeNext and Bundler must resolve the same five declarations under every condition set. Vite client and default webworker SSR retain the browser stub; explicit worker conditions load server modules; unknown conditions exercise the default server fallback.

Artifacts in `analysis/ssr-worker` record runtime versions, compatibility settings, resolver/module paths, request results and the Vite bundle. These are import/render/rollback checks, not framework hydration, asynchronous application rendering or a claim about every edge runtime.

References: [Wrangler conditional exports](https://developers.cloudflare.com/workers/wrangler/bundling/#conditional-exports), [local worker API](https://developers.cloudflare.com/workers/testing/unstable_startworker/), [Vite SSR resolver conditions](https://vite.dev/config/ssr-options#ssr-resolve-conditions).
